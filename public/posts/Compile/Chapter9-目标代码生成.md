## 指令集架构

![image-20251202163416814](https://circlecoder05.oss-cn-beijing.aliyuncs.com/test/202512021634707.png)

不同：算术逻辑单元ALU对存储单元的访问方式不同

### 栈式

类似于P-code和Java虚拟机

```
C=A+B

代码：
    PUSH A
    PUSH B
    ADD
    POP C
```

### 累加器式

```
C=A+B

代码：
    LOAD A
    ADD B
    STORE C
```

- 代码短了，开销不一定小

- 直接访问内存

### 寄存器式

- 寄存器-内存指令集架构：CISC，如x86
- 寄存器-寄存器指令架构：RISC，如ARM、MIPS

- 区别：是否可以直接内存寻址
- 共性：内部有多个寄存器可以直接作为ALU指令的任一操作数

- 优点：
  - 减少内存访问
  - 减少指令数

## 全局寄存器分配

![image-20251202165502882](https://circlecoder05.oss-cn-beijing.aliyuncs.com/test/202512021655944.png)

- 这里我们所说的**全局**是相对于**基本块**而言，而不是程序全局而言，全局寄存器的分配对象主要是函数的局部变量，包括函数入口参数

- 分配原则：优先分配给跨基本块仍然活跃的变量，尤其是循环体内最活跃的变量；局部变量参与全局寄存器分配，但全局变量和静态变量一般不参与全局寄存器分配（寄存器专属于线程，通常是基于线程安全考虑）

### 引用计数法

通过统计变量在函数内被引用的次数，并根据被引用的特点赋予不同的权重，最终为每个变量计算出一个唯一的权值。根据权值的大小排序，将全局寄存器依次分配给权值最大的变量

**原则**：如果一个局部变量被访问的次数较多，那么它获得全局寄存器的机会也较大

**注意**：出现在循环，尤其是内层嵌套循环中的变量的被访问次数应该得到一定的加权

**分配算法**：如果有N个全局寄存器可供分配，则前N个变量拥有全局寄存器，其余变量在程序运行栈（活动记录）分配存贮单元

### 图着色算法

画出变量冲突图，给出寄存器分配方案

如果可供分配 k个全局寄存器，就尝试用 k 种颜色给冲突图着色

1. 找到第一个连接边数目小于K的结点，将它从图G中移走，得到图G'
2. 重复步骤1，直到无法再从G’中移走结点
3. 在图中选取适当 的结点，将它记录为“**不分配全局寄存器**”的结点，并从图中移走
4. 重复**上述所有步骤**，直到图中仅剩余1个结点
5. 按照结点移走的反向顺序将点和边添加回去，并分配颜色

## 临时寄存器分配

临时寄存器中保存有此前的计算中间结果。生存范围：

- 不超越基本块
- 不跨越函数调用

### 临时寄存器池

- 进入基本块时，**清空**临时寄存器池

- 为当前中间代码生成目标代码时，无论临时变量还是局部变量（甚至是全局变量和静态变量），如果需要使用临时寄存器，都可以向**临时寄存器池**申请

- 临时寄存器池接到申请以后，如果寄存器池中有空闲寄存器，则直接把该空闲寄存器拿去使用

- 如果寄存器池中没有空闲寄存器，则选取一个在即将生成的代码中**不会被使用**的寄存器，把这个寄存器中原本存储的值写回相应的内存空间（一般是栈区），标记该寄存器被新的变量占用，把该寄存器返回
- 在基本块结尾，或函数调用发生前，将寄存器池中所有被占用的临时寄存器写回相应的内存空间，清空临时寄存器池
